# Plan: Modernize Project Tech Stack

## Current State Assessment

The project is in good shape overall — it already follows most 2025-2026 VS Code extension best practices (esbuild, ESLint flat config, pnpm, TypeScript strict mode). However, several dependencies are outdated or using deprecated packages.

### Findings

| Component | Current | Latest/Recommended | Status |
|---|---|---|---|
| esbuild | ^0.25.10 | ^0.28.0 | Outdated |
| ESLint | ^9.36.0 | ^10.x | Behind (v10 dropped legacy config support) |
| typescript-eslint | Separate `plugin` + `parser` ^8.45.0 | Consolidated `typescript-eslint` ^8.58.0 | Using deprecated separate packages |
| ESLint config | Custom flat config with manual wiring | `tseslint.config()` helper + recommended presets | Missing base presets, could use type-aware linting |
| TypeScript | ^5.9.3 | 6.0.3 | Fine (official samples still use 5.9) |
| npm-run-all | ^4.1.5 | **Abandoned** | Must replace |
| @vscode/test-cli | ^0.0.11 | ^0.0.12 | Minor bump |
| tsconfig | Good baseline | Missing `skipLibCheck`, `esModuleInterop`, explicit `include`/`exclude` | Minor improvements |
| activationEvents | `[]` (empty) | Implicit inference from contributes | Already correct |

---

## Changes

### 1. Replace `npm-run-all` with `npm-run-all2` (priority: high)

`npm-run-all` is abandoned. `npm-run-all2` is a drop-in replacement maintained by the community and used by VS Code's own built-in extensions.

- Remove `npm-run-all`, add `npm-run-all2` ^8.0.0
- No script changes needed — same CLI interface (`-p` for parallel, `-s` for sequential)

### 2. Switch to consolidated `typescript-eslint` package (priority: high)

The separate `@typescript-eslint/eslint-plugin` and `@typescript-eslint/parser` packages are the old pattern. The `typescript-eslint` meta-package bundles both.

- Remove `@typescript-eslint/eslint-plugin` and `@typescript-eslint/parser`
- Add `typescript-eslint` ^8.58.0
- Refactor `eslint.config.mjs` to use `tseslint.config()` helper with recommended presets

### 3. Update `eslint.config.mjs` (priority: medium)

Refactor to use modern patterns:

```js
import js from '@eslint/js';
import tseslint from 'typescript-eslint';

export default tseslint.config(
  js.configs.recommended,
  ...tseslint.configs.recommended,
  {
    files: ['**/*.ts'],
    languageOptions: {
      parserOptions: {
        projectService: true,
        tsconfigRootDir: import.meta.dirname,
      },
    },
  },
  { ignores: ['dist/**', 'out/**', '*.js', '*.mjs'] },
);
```

Benefits: recommended rule sets, `projectService: true` enables type-aware linting (e.g., `no-floating-promises`).

### 4. Bump esbuild to ^0.28.0 (priority: medium)

Simple version bump. No API changes that affect this project.

### 5. Bump @vscode/test-cli to ^0.0.12 (priority: low)

Minor version bump, no breaking changes.

### 6. Improve tsconfig.json (priority: low)

Add commonly recommended settings:

```json
{
  "compilerOptions": {
    "module": "Node16",
    "moduleResolution": "Node16",
    "target": "ES2022",
    "lib": ["ES2022"],
    "sourceMap": true,
    "rootDir": "src",
    "outDir": "out",
    "strict": true,
    "esModuleInterop": true,
    "skipLibCheck": true,
    "forceConsistentCasingInFileNames": true
  },
  "include": ["src/**/*"],
  "exclude": ["node_modules", "dist", "out"]
}
```

### 7. Upgrade ESLint to v10 (priority: medium)

ESLint 10 removed legacy `.eslintrc` support. Since this project already uses flat config, the upgrade should be seamless. Upgrade from ^9.36.0 to ^10.x.

- Update `eslint` to ^10.x in `package.json` devDependencies
- Also need to add `@eslint/js` package (required for `js.configs.recommended` base config)

---

## Out of Scope (intentionally not changing)

- **TypeScript 6.0** — Official VS Code extension samples still target 5.9. No urgency.
- **VS Code engine** — ^1.105.0 covers a broad user base. Bumping would reduce compatibility for no benefit at this stage.
- **`yo code`** — Still the official scaffolding tool, no replacement exists.
- **Bundler** — esbuild is the standard, Microsoft is actively migrating their own extensions to it.

---

## Execution Order

1. Replace `npm-run-all` → `npm-run-all2` in `package.json`
2. Switch ESLint packages: remove `@typescript-eslint/eslint-plugin` and `@typescript-eslint/parser`, add `typescript-eslint` and `@eslint/js`
3. Upgrade `eslint` to ^10.x in `package.json`
4. Rewrite `eslint.config.mjs` with `tseslint.config()` helper, recommended presets, type-aware linting (`projectService: true`)
5. Bump `esbuild` to ^0.28.0, `@vscode/test-cli` to ^0.0.12 in `package.json`
6. Update `tsconfig.json` with `skipLibCheck`, `esModuleInterop`, `moduleResolution`, `include`/`exclude`
7. Run `pnpm install` to update lockfile
8. Run `pnpm run check-types`, `pnpm run lint`, `pnpm run compile` to verify everything passes
