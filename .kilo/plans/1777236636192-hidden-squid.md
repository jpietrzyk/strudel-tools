# Plan: Add Strudel Playback to VS Code Extension

## Overview

Add Strudel.js live-coding music playback to the extension so users can evaluate `.strudel` files and hear audio directly in VS Code.

### Architecture Decision

```
Extension Host (Node.js)              Sidebar Webview (Browser Context)
┌───────────────────────────┐         ┌─────────────────────────────────┐
│ - Commands: play, stop,   │  ←msg→  │ - @strudel/web (bundled)       │
│   evaluate file           │         │ - Web Audio API synthesis       │
│ - Status bar indicator    │         │ - evaluate() / hush()           │
│ - File type association   │         │ - Connect toggle (autoplay pol) │
│ - Document save watcher   │         │ - Minimal UI (status, connect)  │
└───────────────────────────┘         └─────────────────────────────────┘
```

**Choices:**
- Sidebar panel (WebviewView) — stays visible while editing
- Bundle Strudel with esbuild (offline-capable, ~1.5MB)
- `.strudel` file support only

## Phase 1: Project Setup & Dependencies

### 1.1 Install Strudel packages

Add `@strudel/web` as a runtime dependency:

```bash
pnpm add @strudel/web
```

This umbrella package includes `@strudel/core`, `@strudel/mini`, `@strudel/tonal`, `@strudel/webaudio`, `@strudel/transpiler`.

### 1.2 Update esbuild config for dual build

`esbuild.js` currently builds only the extension host. Add a second build target for the webview:

```js
// Extension host build (existing)
{
  entryPoints: ['src/extension.ts'],
  bundle: true,
  format: 'cjs',
  minify: production,
  sourcemap: !production,
  platform: 'node',
  outfile: 'dist/extension.js',
  external: ['vscode'],
},

// Webview build (new)
{
  entryPoints: ['src/webview/main.ts'],
  bundle: true,
  format: 'iife',
  minify: production,
  sourcemap: !production,
  platform: 'browser',
  target: ['es2021'],
  outfile: 'dist/webview.js',
},
```

Key difference: webview uses `format: 'iife'` and `platform: 'browser'` since it runs in a browser context without module support.

### 1.3 Update tsconfig.json

No changes needed — the existing config already covers `src/**/*` which includes the new `src/webview/` directory.

### 2.3 Implement WebviewViewProvider

Create `src/strudelView.ts`:

```typescript
import * as vscode from 'vscode';

export class StrudelView implements vscode.WebviewViewProvider {
  public static readonly viewType = 'strudel-tools.playerView';
  private _view?: vscode.WebviewView;

  constructor(private readonly _extensionUri: vscode.Uri) {}

  public resolveWebviewView(webviewView: vscode.WebviewView): void {
    this._view = webviewView;
    webviewView.webview.options = {
      enableScripts: true,
      retainContextWhenHidden: true,
      localResourceRoots: [this._extensionUri],
    };
    webviewView.webview.html = this._getHtmlForWebview(webviewView.webview);

    webviewView.webview.onDidReceiveMessage((msg) => {
      switch (msg.type) {
        case 'status':
          // Update status bar
          break;
        case 'error':
          vscode.window.showErrorMessage(msg.value);
          break;
      }
    });
  }

  public sendCode(code: string): void {
    this._view?.webview.postMessage({ command: 'evaluate', code });
  }

  public stop(): void {
    this._view?.webview.postMessage({ command: 'stop' });
  }
}
```

### 2.4 Wire up extension.ts

In `activate()`:

- Instantiate `StrudelView` and register with `vscode.window.registerWebviewViewProvider`
- Register `strudel-tools.play` command — reads active `.strudel` file, calls `strudelView.sendCode(code)`
- Register `strudel-tools.stop` command — calls `strudelView.stop()`
- Register `strudel-tools.evaluate` command — reads selected text, calls `strudelView.sendCode(code)`
- Add status bar item showing play/stop state

### 2.5 Webview HTML generation

Generate HTML with:

```html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta http-equiv="Content-Security-Policy"
    content="default-src 'none';
             script-src ${webview.cspSource};
             style-src ${webview.cspSource};
             connect-src https:;">
  <link href="${styleUri}" rel="stylesheet">
</head>
<body>
  <div id="status">Click connect to start</div>
  <button id="connect">Connect Audio</button>
  <script src="${scriptUri}"></script>
</body>
</html>
```

The `connect-src https:` CSP directive is required because Strudel fetches audio samples from GitHub at runtime.

## Phase 3: Webview (`src/webview/`)

### 3.1 Create `src/webview/main.ts`

```typescript
import { initStrudel, evaluate, hush, samples } from '@strudel/web';

const vscode = acquireVsCodeApi();
let connected = false;

async function connect() {
  await initStrudel({
    prebake: () => samples('github:tidalcycles/dirt-samples'),
  });
  connected = true;
  vscode.postMessage({ type: 'status', value: 'connected' });
}

async function play(code: string) {
  if (!connected) { await connect(); }
  try {
    await evaluate(code);
    vscode.postMessage({ type: 'status', value: 'playing' });
  } catch (e) {
    vscode.postMessage({ type: 'error', value: String(e) });
  }
}

function stop() {
  hush();
  vscode.postMessage({ type: 'status', value: 'stopped' });
}

// UI bindings
document.getElementById('connect')?.addEventListener('click', connect);

// Message handler from extension host
window.addEventListener('message', (event) => {
  const message = event.data;
  switch (message.command) {
    case 'evaluate': play(message.code); break;
    case 'stop': stop(); break;
  }
});
```

Minimal styling for the sidebar webview — status text, connect button, VS Code theme-aware colors using CSS variables (`var(--vscode-foreground)`, `var(--vscode-button-background)`, etc.).
