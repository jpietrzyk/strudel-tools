# Plan: Fix Strudel Playback — CSP-Safe Evaluator (Continued)

## Current Status

**Build passes.** Implementation is complete but **not yet tested** in the Extension Development Host.

### What's been done:
1. **Root cause identified**: `evaluate()` from `@strudel/web` uses `Function()` constructor, blocked by VS Code webview CSP. Error silently swallowed.
2. **CSP-safe evaluator implemented** in `src/webview/main.ts`:
   - Uses strudel `transpiler()` (text→text transform) on user code
   - Parses output with `acorn.parse()` into AST
   - Walks AST recursively against `globalThis` (no `Function()` needed)
   - Feeds resulting Pattern to `repl.setPattern(pattern, true)` directly
3. **AudioWorklets disabled** (`disableWorklets: true`) — VS Code webview limitation
4. **All imports from `@strudel/web` only** — sub-packages not directly resolvable in pnpm
5. **`acorn` added as direct dependency**
6. **Build passes** (`pnpm run compile` succeeds, webview.js = 1.2MB)

7. Run "Strudel: Stop Playback"

### Step 2: Debug if needed

Based on testing, there may be issues with:
- **AST evaluator missing node types** — if transpiler produces unexpected AST nodes (e.g., `TemplateLiteral`, `ConditionalExpression`, `ArrowFunctionExpression`)
- **`evalScope` not loading all needed functions** — if certain strudel functions aren't available on `globalThis`
- **`repl.setPattern()` not accepting the evaluated result** — if the pattern type doesn't match what the scheduler expects

Each of these will surface as an error in the Strudel output channel (logged via `log()` function).

### Step 3: Handle potential AST evaluator gaps

The current evaluator supports:
- `Program`, `ExpressionStatement`, `ReturnStatement`
- `Literal`, `Identifier`
- `CallExpression`, `MemberExpression`
- `BinaryExpression`, `UnaryExpression`
- `ArrayExpression`, `ObjectExpression`
- `ChainExpression`, `SequenceExpression`, `ParenthesizedExpression`

Not yet supported (may be needed):
- `TemplateLiteral` — e.g., `` note(`c3 ${variable}`) ``
- `ConditionalExpression` — e.g., `x ? a : b`
- `ArrowFunctionExpression` — e.g., patterns with custom functions
- `VariableDeclaration` — e.g., `let x = ...`
- `AssignmentExpression` — e.g., `x = ...`

These should be added only if testing shows they're needed for typical strudel patterns.

## Known Limitations

1. **No AudioWorklet sounds** — `disableWorklets: true` means supersaw, pulse, bytebeat won't work. Basic oscillators and samples work.
2. **No `Function()`/`eval()`** — by design, for CSP compliance. The safe evaluator is the only option.
3. **AST evaluator scope** — covers ~90% of typical strudel patterns. Complex patterns with variables/functions may not work yet.
